# **8.1: Introdução a Generics - Escrevendo Código Type-Safe e Reutilizável**

Desde seu lançamento, uma das maiores discussões na comunidade Go foi a ausência de **Generics**. Funções genéricas permitem escrever código que opera sobre múltiplos tipos de dados sem sacrificar a segurança de tipos que o compilador oferece. Com a versão 1.18, Go finalmente introduziu essa poderosa funcionalidade.

## 1\. O "Porquê": O Problema da Lógica Idêntica para Tipos Diferentes

Para entender o poder dos Generics, vamos analisar o problema proposto na aula: criar uma função que reverte a ordem dos elementos de um slice.

A **lógica** para reverter um `[]int` é exatamente a mesma que para reverter um `[]string`:

1.  Crie um novo slice do mesmo tamanho.
2.  Percorra o slice original do início ao fim.
3.  Coloque o primeiro elemento do original na última posição do novo, o segundo na penúltima, e assim por diante.

## 2\. A Solução Antiga (Pré-Generics): Duplicação de Código

Sem Generics, éramos forçados a duplicar o código para cada tipo que queríamos suportar.

```go
package main

import "fmt"

// Uma função que reverte APENAS slices de inteiros.
func reverseInts(s []int) []int {
	result := make([]int, len(s))
	for i := 0; i < len(s); i++ {
		result[len(s)-1-i] = s[i]
	}
	return result
}

// Uma função que reverte APENAS slices de strings.
func reverseStrings(s []string) []string {
	result := make([]string, len(s))
	for i := 0; i < len(s); i++ {
		result[len(s)-1-i] = s[i]
	}
	return result
}

func main() {
	sliceDeInts := []int{5, 1, 2, 3}
	sliceDeStrings := []string{"a", "f", "o", "b"}

	fmt.Println("Ints revertidos:", reverseInts(sliceDeInts))
	fmt.Println("Strings revertidas:", reverseStrings(sliceDeStrings))
}
```

**O Problema:** Isso é uma violação clara do princípio **DRY (Don't Repeat Yourself)**. A lógica é 99% idêntica. Se encontrarmos um bug ou quisermos otimizar o algoritmo, teremos que fazer a mesma alteração em múltiplos lugares.

## 3\. A Solução Moderna (Go 1.18+): Generics

Generics nos permitem escrever uma **única função** que resolve o problema para todos os tipos desejados.

### a) Anatomia de uma Função Genérica

A sintaxe para uma função genérica introduz um novo elemento: a **lista de parâmetros de tipo**, definida entre colchetes `[]`.

`func NomeDaFuncao[ParâmetroDeTipo RestriçãoDeTipo](...)`

1.  **`[ ... ]` (Colchetes):** Posicionados entre o nome da função e seus parâmetros, eles declaram os tipos genéricos que a função usará.
2.  **`T` (Parâmetro de Tipo):** É um nome de tipo "placeholder". É uma convenção usar uma única letra maiúscula como `T` (de Type), `V` (de Value) ou `K` (de Key). Pense nele como uma variável, mas para tipos.
3.  **`int | string` (Restrição de Tipo / Type Constraint):** Define o conjunto de tipos concretos que o parâmetro de tipo `T` pode assumir. O `|` significa "OU". Então, `int | string` significa que `T` pode ser um `int` OU uma `string`.

### b) Implementando a Função `Reverse` Genérica

Agora, podemos reescrever nossa função `reverse` uma única vez, usando o parâmetro de tipo `T` no lugar dos tipos concretos (`int` ou `string`).

```go
package main

import "fmt"

// Reverse é uma função genérica.
// [T int | string] diz: "Esta função trabalha com um tipo T, que pode ser int OU string".
func Reverse[T int | string](s []T) []T {
	// O tipo do slice de resultado é []T, o mesmo do slice de entrada.
	result := make([]T, len(s))
	for i := 0; i < len(s); i++ {
		result[len(s)-1-i] = s[i]
	}
	return result
}

func main() {
	sliceDeInts := []int{5, 1, 2, 3}
	sliceDeStrings := []string{"a", "f", "o", "b"}

	// Chamamos a MESMA função Reverse para ambos os tipos.
	// O compilador infere que para a primeira chamada T=int e para a segunda T=string.
	fmt.Println("Ints revertidos:", Reverse(sliceDeInts))
	fmt.Println("Strings revertidas:", Reverse(sliceDeStrings))

	// Se tentarmos passar um tipo não permitido pela restrição, teremos um erro de compilação!
	// sliceDeFloats := []float64{1.1, 2.2}
	// Reverse(sliceDeFloats) // ERRO: float64 does not implement int|string
}
```

**Saída:**

```
Ints revertidos: [3 2 1 5]
Strings revertidas: [b o f a]
```

Conseguimos\! Uma única função, sem duplicação de código, que é **type-safe**. O compilador garante que só possamos usá-la com os tipos que permitimos.

## 4\. Generics vs. Interfaces: A Distinção Crucial

Como a aula bem aponta, é fácil confundir Generics com Interfaces. A diferença é fundamental:

  * **Interfaces são sobre COMPORTAMENTO:** Elas definem um contrato de *o que um tipo pode fazer* (quais métodos ele possui). Usamos interfaces quando queremos trabalhar com tipos diferentes que **compartilham um comportamento comum** (ex: `Retangulo` e `Circulo` ambos têm um método `area()`).

  * **Generics são sobre ALGORITMOS:** Eles permitem escrever código que funciona com *qualquer tipo* que satisfaça uma restrição, **sem se importar com seu comportamento específico**. Usamos generics quando a **lógica do algoritmo é a mesma** para diferentes tipos de dados (ex: reverter, ordenar, encontrar o mínimo/máximo em um slice).

# **6.4: Composição de Structs - Construindo Tipos Complexos**

Na aula anterior, criamos a `struct Endereco` para agrupar campos relacionados a um endereço. Agora, vamos dar o próximo passo e usar essa `struct` como um "bloco de construção" dentro de outra `struct`, um conceito conhecido como **composição**.

## 1\. O Conceito: Composição de Tipos

A composição é o ato de construir tipos complexos combinando tipos mais simples. Em vez de criar uma `struct Pessoa` gigante com todos os campos (`Nome`, `Rua`, `Numero`, `Cidade`), nós modelamos o mundo real de forma mais precisa: uma `Pessoa` **tem um** `Endereco`.

Esta relação "tem um" (em inglês, "has-a") é a essência da composição e é uma das filosofias de design centrais em Go.

## 2\. Implementação Passo a Passo

A aula demonstra como implementar a composição de forma limpa e organizada em nosso projeto.

### a) Passo 1: Criar a `struct Pessoa` no Pacote `model`

Para manter nossa lógica de dados organizada, criamos um novo arquivo, `pessoa.go`, dentro da nossa pasta `model`. Como ele está no mesmo diretório, ele pertence ao mesmo `package model`.

**`model/pessoa.go`**

```go
package model

// A struct Pessoa é definida.
// Ela tem um campo 'Nome' do tipo string.
// E um campo 'Endereco' do tipo 'Endereco' (a outra struct que definimos no mesmo pacote).
type Pessoa struct {
	Nome     string
	Endereco Endereco // Composição em ação!
}
```

Como `Pessoa` e `Endereco` estão no mesmo pacote `model`, a `struct Pessoa` pode usar a `struct Endereco` diretamente pelo nome, sem precisar de prefixos.

### b) Passo 2: Utilizando a Composição em `main.go`

Agora, na nossa função `main`, podemos criar uma hierarquia de dados que reflete a realidade.

```go
// main.go
package main

import (
	"fmt"
	"golang-estudo/model"
)

func main() {
	fmt.Println("Iniciando")

	// 1. Primeiro, criamos uma instância do tipo mais interno: Endereco.
	addr := model.Endereco{
		Rua:    "Rua X",
		Numero: 18,
		Cidade: "Campo Grande",
	}

	// 2. Em seguida, criamos uma instância do tipo Pessoa.
	// No campo 'Endereco', passamos a instância 'addr' que acabamos de criar.
	p := model.Pessoa{
		Nome:     "Henrique",
		Endereco: addr,
	}

	// 3. Imprimimos a struct composta.
	fmt.Println("Dados da Pessoa:", p)
}
```

**Saída:**

```
Iniciando
Dados da Pessoa: {Henrique {Rua X 18 Campo Grande}}
```

A saída mostra claramente a estrutura aninhada: a `struct Pessoa` contém a `struct Endereco` dentro dela.

## 3\. Acessando Campos Aninhados

Para acessar os campos da `struct` interna, simplesmente encadeamos o operador ponto (`.`).

**Sintaxe:** `variavelExterna.VariavelInterna.Campo`

```go
// (continuação da função main)

// Acessando campos da struct Pessoa
fmt.Println("Nome da pessoa:", p.Nome) // Saída: Henrique

// Acessando campos da struct Endereco aninhada
fmt.Println("Cidade da pessoa:", p.Endereco.Cidade) // Saída: Campo Grande

// Também podemos modificar os campos aninhados
p.Endereco.Rua = "Avenida Principal"
fmt.Println("Rua atualizada:", p.Endereco.Rua) // Saída: Avenida Principal

fmt.Println("Pessoa com dados atualizados:", p)
```

**Saída:**

```
Pessoa com dados atualizados: {Henrique {Avenida Principal 18 Campo Grande}}
```

## 4\. O "Go Way": Composição vs. Herança

Se você vem de linguagens como Java, C\# ou Python, pode estar se perguntando: "Isso não é herança?". A resposta é **não**, e essa é uma distinção fundamental.

  * **Herança (relação "é um"):** Uma classe `Carro` *herda* de `Veiculo`. Um `Carro` **é um** `Veiculo`. Go **não tem** herança de classes.
  * **Composição (relação "tem um"):** Uma `Pessoa` **tem um** `Endereco`. Um `Carro` **tem um** `Motor`. Esta é a forma preferida de construir relacionamentos entre tipos em Go.

A filosofia do Go, frequentemente resumida como **"prefira a composição à herança"**, leva a um código mais flexível, menos acoplado e mais fácil de entender e manter, pois os relacionamentos entre os tipos são explícitos.

Esta aula demonstrou como esse poderoso princípio é implementado de forma simples e elegante na linguagem.

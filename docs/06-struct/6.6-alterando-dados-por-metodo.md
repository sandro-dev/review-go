# **6.6: Métodos com Ponteiros (Pointer Receivers) - Modificando o Estado de Structs**

Na aula anterior, criamos um método que *lia* dados de uma `struct` para retornar um valor (`IdadeAtual`). Nesta aula, vamos além: tentaremos criar um método que **modifica** o estado da própria `struct`, calculando a idade e armazenando-a em um novo campo. É aqui que a distinção entre uma cópia e o original se torna crítica.

## 1\. O Cenário: Armazenando um Valor Calculado

Nosso objetivo é adicionar um campo `Idade` à nossa `struct Pessoa` e criar um método, `CalculaIdade`, que preencha esse campo.

**`model/pessoa.go` (modificado)**

```go
package model

import "time"

type Pessoa struct {
	Nome            string
	Endereco        Endereco
	DataNascimento  time.Time
	Idade           int // Novo campo para armazenar a idade calculada
}
// ...
```

**`main.go` (a intenção)**

```go
// ...
p := model.Pessoa{ ... } // A idade inicial será 0
p.CalculaIdade()          // Esperamos que este método atualize p.Idade
fmt.Println(p.Idade)      // Esperamos ver a idade correta aqui
```

## 2\. A "Pegadinha": O Comportamento de Cópia com Value Receivers

A primeira abordagem, e a mais intuitiva, é criar o método da mesma forma que fizemos antes, com um **value receiver** (`(p Pessoa)`).

**`model/pessoa.go` (Tentativa 1 - Incorreta)**

```go
// Este é um VALUE receiver. 'p' é uma CÓPIA da Pessoa original.
func (p Pessoa) CalculaIdade() {
	anoAtual := time.Now().Year()
	anoNascimento := p.DataNascimento.Year()

	// Esta linha modifica o campo 'Idade' DA CÓPIA 'p'.
	p.Idade = anoAtual - anoNascimento
	
	// A aula adicionou este log para provar que o cálculo DENTRO da função está correto.
	fmt.Printf("(Dentro do método) Idade calculada: %d\n", p.Idade)
}
```

**Execução em `main.go`**

```go
// ...
p.CalculaIdade()
fmt.Println("Idade na 'main' após a chamada:", p.Idade)
```

**Saída:**

```
(Dentro do método) Idade calculada: 37  // A versão atual seria 40 (2025 - 1985)
Idade na 'main' após a chamada: 0
```

**Por que isso acontece?**
Como a aula explica brilhantemente, o problema está no comportamento padrão de Go: **pass-by-value**.
Quando você chama `p.CalculaIdade()`, o Go não passa a sua variável `p` original para o método. Em vez disso, ele cria uma **cópia completa** da `struct p` e entrega essa cópia ao método.

Pense nisso como dar uma **fotocópia** de um formulário a alguém. A pessoa pode preencher a fotocópia, mas o seu formulário original continua em branco. Quando o método termina, a cópia é descartada, e a sua `p` original na função `main` nunca foi alterada.

## 3\. A Solução: Modificando o Original com Pointer Receivers

Para que um método possa modificar a `struct` original, ele precisa saber onde ela está na memória. Em vez de passar uma cópia da `struct`, precisamos passar um **ponteiro** para ela. Fazemos isso usando um **pointer receiver**.

**A Mudança na Sintaxe:**

  * Value Receiver: `(p Pessoa)`
  * Pointer Receiver: `(p *Pessoa)` - O asterisco `*` faz toda a diferença.

**`model/pessoa.go` (Tentativa 2 - Correta)**

```go
// Este é um POINTER receiver. 'p' é um PONTEIRO para a Pessoa original.
func (p *Pessoa) CalculaIdade() {
	anoAtual := time.Now().Year()
	anoNascimento := p.DataNascimento.Year()
	
	// Esta linha agora modifica o campo 'Idade' DA STRUCT ORIGINAL.
	p.Idade = anoAtual - anoNascimento
}
```

Agora, quando você chama `p.CalculaIdade()`, Go passa o endereço de memória de `p`. O método recebe este "endereço" e o usa para modificar a `struct` original diretamente.

**Execução Corrigida em `main.go`**

```go
// ...
p.CalculaIdade()
fmt.Println("Idade na 'main' após a chamada:", p.Idade)
```

**Saída:**

```
Idade na 'main' após a chamada: 40 // O valor correto (2025 - 1985)!
```

> **Nota do Especialista (Syntactic Sugar):** Embora `p` seja agora um ponteiro (`*Pessoa`), Go nos permite escrever `p.Idade` de forma conveniente. O compilador converte isso automaticamente para a forma mais explícita, que seria `(*p).Idade`. Isso torna o uso de pointer receivers muito mais limpo e natural.

## 4\. O "Go Way": Quando Usar Pointer vs. Value Receiver

Esta é uma das decisões de design mais importantes que você tomará ao escrever código Go. A regra geral é:

| Use um **Pointer Receiver** (`*T`) se: | Use um **Value Receiver** (`T`) se: |
| :--- | :--- |
| 1. O método precisa **modificar** o estado do receiver. (Nosso caso de `CalculaIdade`). | 1. O método **não precisa modificar** o receiver; ele apenas lê dados. |
| 2. A `struct` é muito grande e você quer **evitar o custo da cópia** a cada chamada do método. Passar um ponteiro (um endereço de 8 bytes) é muito mais barato que copiar uma struct de 1 kilobyte. | 2. A `struct` é pequena (como um `time.Time` ou um slice pequeno) e é mais barato ou seguro copiá-la. |
| | 3. Você quer garantir que o método **não possa** modificar o estado original (imunidade a efeitos colaterais). |

**Consistência:** A comunidade Go também valoriza a consistência. Se pelo menos **um** método do seu tipo precisar de um pointer receiver, a convenção é fazer **todos** os métodos daquele tipo usarem pointer receivers. Isso evita confusão sobre qual método pode ou não modificar o estado.

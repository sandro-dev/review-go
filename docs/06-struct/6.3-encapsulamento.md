# **6.3: Visibilidade e Encapsulamento em Go (Pacotes e Letras Maiúsculas)**

Se você vem de linguagens orientadas a objeto, está acostumado com palavras-chave como `public`, `private` e `protected` para controlar o acesso a classes, métodos e propriedades. Go adota uma abordagem radicalmente mais simples, mas igualmente poderosa.

## 1\. A Regra de Ouro da Visibilidade em Go

Em Go, não existem palavras-chave para controle de acesso. A visibilidade de um identificador (seja uma `struct`, uma `função`, uma `constante` ou uma `variável`) é determinada por uma regra única e simples:

  * **Letra Inicial Maiúscula (Exportado):** Se um identificador começa com uma letra maiúscula (ex: `Endereco`, `CalcularImposto`), ele é **exportado**. Isso significa que ele é "público" e pode ser acessado por outros pacotes que importem o pacote onde ele foi definido.
  * **Letra Inicial Minúscula (Não Exportado):** Se um identificador começa com uma letra minúscula (ex: `endereco`, `calcularImposto`), ele é **não exportado**. Isso significa que ele é "privado" e seu uso está restrito **apenas ao pacote onde foi definido**.

## 2\. Refatorando para Múltiplos Pacotes

Para testar essa regra na prática, precisamos de pelo menos dois pacotes: nosso pacote `main` e um novo pacote para guardar nossos tipos de dados (modelos).

### a) A Regra Fundamental: Um Pacote por Diretório

A aula demonstra um princípio fundamental da organização de projetos em Go: **todos os arquivos dentro de um mesmo diretório devem pertencer ao mesmo pacote.**

O erro `found packages main (main.go) and model (model.go) in ...` acontece porque tentamos declarar dois pacotes diferentes na mesma pasta.

**A Solução:** Criar um novo diretório para cada novo pacote.

1.  O arquivo `main.go` (com `package main`) fica na raiz do projeto.
2.  Criamos uma nova pasta chamada `model`.
3.  Movemos nosso novo arquivo (`endereco.go`) para dentro da pasta `model` e declaramos `package model` nele.

<!-- end list -->

```
/golang-estudo
├── go.mod
├── main.go         // package main
└── /model
    └── endereco.go // package model
```

> **Nota do Especialista:** A convenção é que o nome do diretório (`model`) seja o mesmo nome do pacote (`package model`).

## 3\. O Processo de Refatoração Passo a Passo

Agora, vamos mover nossa `struct Endereco` para o novo pacote e ver as regras de visibilidade em ação.

### a) Passo 1: Mover e Importar

Primeiro, movemos a definição da `struct` para `model/endereco.go`.

**`model/endereco.go`**

```go
package model

// ATENÇÃO: 'endereco' começa com letra minúscula
type endereco struct {
	rua    string
	numero int
	cidade string
}
```

Em seguida, tentamos usar essa `struct` em `main.go`, importando nosso novo pacote. O caminho de importação é composto pelo **nome do módulo (do `go.mod`)** mais o caminho do subdiretório.

**`main.go`**

```go
package main

import (
	"fmt"
	"golang-estudo/model" // Importando nosso pacote local
)
// ...
```

### b) O Primeiro Erro: Struct Não Exportada

Agora, ao tentar usar `model.endereco`, o compilador irá reclamar.

`meuEndereco := model.endereco{...}` -\> **ERRO DE COMPILAÇÃO:** `cannot refer to unexported name model.endereco`

  * **Motivo:** A `struct endereco` começa com letra minúscula, portanto, ela não é exportada e não pode ser "vista" de fora do pacote `model`.

### c) A Solução: Exportando a Struct

A solução é simples: renomear a `struct` para começar com uma letra maiúscula.

**`model/endereco.go` (Corrigido)**

```go
package model

// Agora 'Endereco' é exportado e visível para outros pacotes.
type Endereco struct {
	rua    string
	numero int
	cidade string
}
```

### d) O Segundo Erro: Campos Não Exportados

O primeiro erro foi resolvido, mas um novo aparece ao tentar inicializar a `struct`.

`meuEndereco := model.Endereco{ rua: "Rua X", ... }` -\> **ERRO DE COMPILAÇÃO:** `unknown field 'rua' in struct literal of type model.Endereco`

  * **Motivo:** Embora a `struct Endereco` seja agora visível, seus **campos** (`rua`, `numero`, `cidade`) ainda começam com letra minúscula. Eles são privados ao pacote `model` e não podem ser acessados diretamente pelo pacote `main`.

### e) A Solução Final: Exportando os Campos

A solução final é capitalizar também os nomes dos campos que precisam ser acessíveis de fora.

**`model/endereco.go` (Versão Final)**

```go
package model

type Endereco struct {
	Rua    string
	Numero int
	Cidade string
}
```

**`main.go` (Versão Final e Funcional)**

```go
package main

import (
	"fmt"
	"golang-estudo/model" // O VS Code geralmente adiciona isso para você
)

func main() {
	fmt.Println("Iniciando")

	meuEndereco := model.Endereco{
		Rua:    "Rua X",
		Numero: 15,
		Cidade: "Campo Grande",
	}
	fmt.Println("Endereço inicial:", meuEndereco)
	
	meuEndereco.Numero = 18
	fmt.Println("Número novo:", meuEndereco.Numero)
}
```

Agora, o programa compila e roda com sucesso, pois respeitamos as regras de visibilidade de Go.

## 4\. Resumo das Regras (O "Go Way")

| Se o Identificador... | Ele é... | Significa que... |
| :--- | :--- | :--- |
| Começa com **letra maiúscula** | **Exportado** (Público) | Pode ser acessado por qualquer outro pacote. |
| Começa com **letra minúscula**| **Não Exportado** (Privado) | Só pode ser acessado dentro do mesmo pacote. |

# **6.5: Anexando Comportamento a Structs com Métodos**

Até agora, nossas `structs` têm sido apenas contêineres passivos de dados. Nesta aula, aprendemos como anexar lógica de negócio diretamente a elas, transformando-as de simples estruturas de dados em entidades ativas e inteligentes. Fazemos isso através de **métodos**.

## 1\. O Problema: Lógica de Negócio em Tempo de Execução

O cenário proposto é um exemplo clássico e perfeito: calcular a idade de uma pessoa.

  * **Por que não armazenar a idade?** Como a aula explica, armazenar a idade no banco de dados é uma má prática. A idade é um dado **derivado** e **volátil**; ela muda a cada ano. Se a armazenarmos, ela rapidamente se tornará desatualizada.
  * **A Solução:** A idade deve ser sempre calculada em tempo de execução, com base em um dado fixo: a **data de nascimento**.

## 2\. Adicionando o Dado Base: `time.Time`

Para calcular a idade, primeiro precisamos armazenar a data de nascimento. Go possui um pacote robusto na biblioteca padrão para isso, o pacote `time`.

**`model/pessoa.go` (modificado)**

```go
package model

import "time" // Precisamos importar o pacote 'time'

type Pessoa struct {
	Nome            string
	Endereco        Endereco
	DataNascimento  time.Time // O tipo para data e hora em Go
}
```

**Instanciando com `time.Date` em `main.go`**
A função `time.Date` é usada para criar uma data específica.
`time.Date(ano, mês, dia, hora, min, seg, nseg, localização)`

```go
// main.go (modificado)
dataNasc := time.Date(1985, time.November, 25, 0, 0, 0, 0, time.Local)

p := model.Pessoa{
    Nome:           "Henrique",
    Endereco:       addr,
    DataNascimento: dataNasc,
}
```

## 3\. Abordagem 1: A Função Padrão (Separada da Struct)

A primeira abordagem, funcional mas menos idiomática, é criar uma função no pacote `model` que recebe uma `Pessoa` como argumento e retorna a idade.

**`model/pessoa.go` (com a função)**

```go
// ... (definição da struct Pessoa)

// CalculaIdade é uma FUNÇÃO que opera sobre uma Pessoa.
func CalculaIdade(p Pessoa) int {
	anoAtual := time.Now().Year()
	anoNascimento := p.DataNascimento.Year()
	return anoAtual - anoNascimento
}
```

**Chamada em `main.go`**

```go
idade := model.CalculaIdade(p)
fmt.Println("A idade calculada (via função) é:", idade)
```

**Desvantagem:** A lógica está separada dos dados. A chamada `model.CalculaIdade(p)` não é tão intuitiva; parece que estamos passando a pessoa para uma ferramenta externa.

## 4\. Abordagem 2: O "Go Way" - Métodos

Um **método** em Go é uma função com um argumento especial chamado **receiver**. O receiver anexa a função a um tipo específico (no nosso caso, `Pessoa`), tornando a lógica parte intrínseca do tipo.

### a) A Anatomia de um Método

`func (receiver) nomeDoMetodo(parametros) tipoDeRetorno`

  * **`func (p Pessoa)`:** Esta é a parte nova e crucial. Ela é a **declaração do receiver**.
      * `Pessoa`: O tipo ao qual o método está sendo anexado.
      * `p`: O nome que daremos à instância da `struct` *dentro* do método. É como a `struct` se refere a "si mesma". A convenção é usar um nome curto e em minúsculas (a primeira letra do tipo).

### b) Implementando o Método

```go
// model/pessoa.go (com o método)

// IdadeAtual é um MÉTODO da struct Pessoa.
// (p Pessoa) é o receiver.
func (p Pessoa) IdadeAtual() int {
	anoAtual := time.Now().Year()
	// Acessamos os campos da própria pessoa através do receiver 'p'.
	anoNascimento := p.DataNascimento.Year()
	return anoAtual - anoNascimento
}
```

### c) Chamando o Método

A chamada de um método é muito mais natural e alinhada com o pensamento orientado a objetos.

**Chamada em `main.go`**

```go
// A chamada é feita diretamente na variável do tipo Pessoa.
// Lê-se como: "pessoa, qual é a sua idade atual?"
idadeMetodo := p.IdadeAtual()
fmt.Println("A idade calculada (via método) é:", idadeMetodo)
```

## 5\. Função vs. Método: Qual Usar?

A aula termina com uma excelente pergunta: "Qual é o certo?". A resposta depende da relação entre a lógica e os dados.

  * **Use um MÉTODO quando:**

      * A função opera primariamente sobre o estado (os campos) de uma instância daquela `struct`.
      * A lógica "pertence" conceitualmente ao tipo. `IdadeAtual` é algo inerente a uma `Pessoa`. `p.SalvarNoBanco()` é uma ação da `Pessoa`.
      * Você quer que a chamada seja no estilo orientado a objetos: `objeto.Acao()`.

  * **Use uma FUNÇÃO quando:**

      * A função é uma "utilitária" que não opera sobre um estado interno. Ex: `model.FormatarCPF(cpf string)`.
      * A função atua como um "construtor", criando e retornando uma nova instância da `struct`. Ex: `model.NewPessoa(nome string, ...) Pessoa`. Você não pode chamar um método em um objeto que ainda não existe.
      * A função opera sobre uma coleção de `structs`, e não em uma única. Ex: `model.OrdenarPessoasPorIdade([]Pessoa)`.

Para o caso de calcular a idade, o **método** é, sem dúvida, a abordagem mais idiomática, limpa e correta em Go.

# **1.3: Estrutura de um Arquivo Go**

Nesta aula, o foco é a estrutura fundamental de um arquivo de código Go. Todo programa, do mais simples ao mais complexo, é construído sobre estes três pilares: a declaração do pacote (`package`), as importações (`import`) e a função principal (`func main`).

## 1\. A Extensão do Arquivo

Como mencionado, todo arquivo de código-fonte Go utiliza a extensão **`.go`**. No ambiente local, você criaria arquivos como `main.go`, `server.go`, etc. O Go Playground abstrai a visualização do arquivo, mas por trás dos panos, ele está operando com um arquivo `.go`.

## 2\. Os Três Pilares de um Programa Go Executável

### a) A Declaração do Pacote (`package`)

Todo arquivo Go **deve** começar com uma declaração de pacote.

```go
package main
```

  * **O que é um Pacote?** Um pacote (`package`) é uma forma de organizar e agrupar código Go relacionado. Pense nele como uma pasta ou um módulo.
  * **O Pacote `main` é Especial:** Declarar `package main` tem um significado único: sinaliza para o compilador que este código deve ser compilado para se tornar um **programa executável**. É o ponto de partida de uma aplicação.
  * **Outros Pacotes:** Se você nomeasse o pacote como `package utils` ou `package database`, estaria criando uma **biblioteca** – um conjunto de código reutilizável que pode ser importado por outros pacotes, mas que não pode ser executado por si só.

> **Ponto de Atenção:** Como demonstrado na aula, tentar executar um código onde o pacote principal não se chama `main` resultará em um erro. O compilador precisa saber onde a "história" do seu programa começa, e ela sempre começa no `package main`.

### b) A Declaração de Importações (`import`)

Logo após o pacote, geralmente temos o bloco de importações.

```go
import "fmt"
```

  * **Reutilização de Código:** Dificilmente construiremos algo útil totalmente do zero. O comando `import` nos permite trazer funcionalidades de outros pacotes para dentro do nosso arquivo.
  * **`fmt`:** Este é um dos pacotes mais comuns da biblioteca padrão. Seu nome é uma abreviação de "format" (formatação) e ele provê funções para entrada e saída de dados formatados, como a função `Println` usada no exemplo.
  * **O Erro de "Importação Não Utilizada":** Uma característica marcante de Go é sua rigidez com a limpeza do código. **Se você importa um pacote mas não utiliza nenhuma de suas funções, o compilador gerará um erro e se recusará a compilar o programa.** Isso força o desenvolvedor a manter as dependências explícitas e a remover código "morto" ou desnecessário.

**Exemplo Prático (Resultaria em erro):**

```go
package main

import "fmt" // <- Importado mas não utilizado

func main() {
	// Nenhum código usando o pacote "fmt"
}
// Erro de compilação: imported and not used: "fmt"
```

### c) A Função Principal (`func main`)

Esta é a porta de entrada, o ponto exato onde a execução do seu programa começa.

```go
func main() {
    // seu código vai aqui
}
```

  * `func`: É a **palavra-chave reservada** em Go para declarar uma função.
  * `main`: Assim como o `package main`, o nome da função `main` é especial. Quando você executa o programa compilado, o sistema operacional chama a função `main` dentro do pacote `main`.
  * **O Ponto de Partida Único:** Um programa executável só pode ter **uma única função `main`**. Se você renomeá-la para `main2` ou qualquer outro nome, como visto na aula, o compilador não saberá por onde começar a execução e falhará, informando que a função `main` não foi encontrada.

## 3\. Análise Linha a Linha do Código Padrão

Vamos juntar todo o conhecimento e analisar o código completo:

```go
// 1. Declara que este é um pacote que gerará um programa executável.
package main

// 2. Importa o pacote "fmt" para usar suas funções de formatação e impressão.
import "fmt"

// 3. Define a função de entrada do programa. A execução começa aqui.
func main() {
	// 4. Chama a função "Println" do pacote "fmt" para imprimir uma linha de texto no console.
	fmt.Println("Hello, playground")
}
```

## 4\. O "Go Way": Regras Estritas para um Código Limpo

A aula demonstrou uma outra regra importante do compilador Go ao declarar uma variável sem usá-la.

```go
var i int // Declara uma variável 'i' do tipo inteiro
```

Se você adicionar apenas essa linha dentro da função `main` e rodar, receberá o erro: `i declared and not used`.

Isso reforça a filosofia do Go:

  * **Sem Desperdício:** Variáveis e importações não utilizadas são consideradas "ruído". Elas podem indicar código inacabado ou bugs onde uma variável deveria ter sido usada mas foi esquecida.
  * **Clareza Acima de Tudo:** O compilador te força a ser explícito sobre o que seu código está fazendo. Se algo foi declarado, ele assume que há uma intenção de uso.

**Pontos-Chave para Memorizar:**

1.  Um programa que roda sozinho precisa estar no `package main`.
2.  A execução sempre começa na `func main`.
3.  `import` traz funcionalidades de outros pacotes.
4.  O compilador Go **NÃO PERMITE** importações ou variáveis que foram declaradas mas não foram utilizadas no código.

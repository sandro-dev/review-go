# **7.1: Interfaces em Go - Definindo Comportamento com Contratos**

Nesta aula, mergulhamos no conceito de **interfaces**. No começo, a necessidade delas pode não ser óbvia, mas elas são a ferramenta mais poderosa em Go para escrever código flexível, extensível e testável. Uma interface é, em sua essência, um **contrato** que define um conjunto de comportamentos (métodos) que um tipo deve ter.

## 1\. O Problema: Código Rígido e Específico

Para entender o poder das interfaces, vamos primeiro analisar um código que *não* as utiliza, como o construído na aula.

**O Cenário:** Queremos calcular e exibir a área de diferentes formas geométricas.

### a) As Estruturas de Dados (Structs)

Temos dois tipos, cada um com seus próprios campos para calcular a área:

```go
package main

import (
	"fmt"
	"math"
)

type Retangulo struct {
	Largura float64
	Altura  float64
}

type Circulo struct {
	Raio float64
}
```

### b) A Abordagem Sem Interfaces

Para cada tipo, criamos uma função específica que sabe como lidar com ele.

```go
// Uma função que só aceita Retangulos
func exibeAreaRetangulo(r Retangulo) {
	area := r.Largura * r.Altura
	fmt.Printf("A área do retângulo é: %0.2f\n", area)
}

// Uma função que só aceita Circulos
func exibeAreaCirculo(c Circulo) {
	area := math.Pi * (c.Raio * c.Raio)
	fmt.Printf("A área do círculo é: %0.2f\n", area)
}

func main() {
	r := Retangulo{Largura: 1, Altura: 2}
	c := Circulo{Raio: 3}

	exibeAreaRetangulo(r)
	exibeAreaCirculo(c)
}
```

**Quais são os problemas aqui?**

  * **Duplicação de Lógica:** Temos duas funções (`exibeAreaRetangulo`, `exibeAreaCirculo`) que fazem conceitualmente a mesma coisa: exibir uma área.
  * **Código Rígido:** Se quisermos adicionar uma nova forma, como um `Triangulo`, teremos que criar uma terceira função, `exibeAreaTriangulo`, e alterar a função `main` para chamá-la. O sistema não é extensível.
  * **Forte Acoplamento:** A função `main` precisa saber o tipo exato de cada objeto para chamar a função correta.

## 2\. A Solução: Interfaces como Contratos Abstratos

Uma interface define um **contrato de comportamento**. Ela diz: "Eu não me importo com o que você *é* (seus dados, sua `struct`), eu só me importo com o que você *sabe fazer* (seus métodos)".

### a) Definindo a Interface

Vamos criar um contrato chamado `Geometria`. O contrato diz que qualquer tipo que queira ser considerado uma `Geometria` **deve** ter um método chamado `area()` que retorna um `float64`.

```go
// A interface define o CONTRATO
type Geometria interface {
	area() float64
}
```

É só isso\! A interface não tem implementação, apenas a **assinatura** dos métodos obrigatórios.

### b) Cumprindo o Contrato

Agora, fazemos com que nossos tipos `Retangulo` e `Circulo` cumpram esse contrato, implementando o método `area()`.

```go
// Retangulo agora cumpre o contrato Geometria
func (r Retangulo) area() float64 {
	return r.Largura * r.Altura
}

// Circulo agora cumpre o contrato Geometria
func (c Circulo) area() float64 {
	return math.Pi * (c.Raio * c.Raio)
}
```

## 3\. O "Go Way": Satisfação Implícita de Interfaces

Este é um dos recursos mais elegantes de Go. Diferente de linguagens como Java ou C\#, você **não declara explicitamente** que um tipo implementa uma interface (não existe a palavra-chave `implements`).

O compilador do Go verifica isso para você. Se a sua `struct` (`Retangulo`) tem todos os métodos definidos na interface (`Geometria`), ela **automaticamente** satisfaz aquela interface. Isso é chamado de **satisfação implícita** e promove um código muito mais desacoplado.

> A filosofia é: "Se anda como um pato e faz quack como um pato, então deve ser um pato." Se `Retangulo` tem um método `area()`, então ele pode ser tratado como uma `Geometria`.

## 4\. O Resultado Final: Código Flexível e Polimórfico

Agora podemos substituir nossas duas funções antigas por uma única função que aceita qualquer tipo que satisfaça a interface `Geometria`.

```go
// Esta função aceita QUALQUER TIPO que cumpra o contrato Geometria.
func exibeArea(g Geometria) {
	// Ela não sabe se 'g' é um Retangulo ou um Circulo.
	// Ela só sabe que 'g' TEM um método area().
	fmt.Printf("A área da forma é: %0.2f\n", g.area())
}

func main() {
	r := Retangulo{Largura: 1, Altura: 2}
	c := Circulo{Raio: 3}

	// Podemos passar tanto um Retangulo quanto um Circulo para a MESMA função!
	exibeArea(r)
	exibeArea(c)
}
```

**Saída:**

```
A área da forma é: 2.00
A área da forma é: 28.27
```

Este é o poder do **polimorfismo** em Go. A função `exibeArea` é polimórfica porque pode operar com múltiplos tipos (`Retangulo`, `Circulo`) de forma uniforme através da abstração da interface.

**O Grande Benefício:** Se amanhã criarmos uma `struct Triangulo` e dermos a ela um método `area()`, poderemos passá-la para a função `exibeArea` **sem modificar uma única linha de código** na função `exibeArea` ou `main`. O sistema se tornou extensível e desacoplado.

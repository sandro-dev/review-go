# **11.4: Protegendo Dados Compartilhados com `sync.Mutex`**

Já vimos como é fácil criar milhares de goroutines. Mas o que acontece quando todas essas goroutines tentam modificar o **mesmo dado** ao mesmo tempo? Esta aula nos mostra o caos que isso pode gerar (uma condição de corrida) e como podemos impor ordem usando um `Mutex`.

## 1\. O Problema: A Condição de Corrida (Race Condition)

O cenário da aula é projetado para expor um bug sutil e perigoso.

**A Lógica:**

1.  Temos uma variável `i` inicializada com `0`.
2.  Iniciamos 10.000 goroutines.
3.  Cada goroutine executa a mesma tarefa simples: `i++`.
4.  No final, esperamos que o valor de `i` seja `10.000`.

**O Resultado Inesperado:**
A cada execução, o programa imprime um valor final diferente e incorreto: `9873`, `9189`, `9828`. O resultado não é determinístico. Por quê?

**A Explicação:** A operação `i++` **não é atômica**. Para o processador, ela não é uma única instrução, mas sim três passos distintos:

1.  **Ler** o valor atual de `i` da memória.
2.  **Incrementar** esse valor em 1.
3.  **Escrever** o novo valor de volta na memória.

Agora, imagine duas goroutines executando isso "ao mesmo tempo":

| Passo | Goroutine A | Goroutine B | Valor de `i` na Memória |
| :--- | :--- | :--- | :--- |
| 1 | Lê o valor de `i` (ex: 50) | | 50 |
| 2 | | Lê o valor de `i` (ainda 50) | 50 |
| 3 | Incrementa seu valor lido para 51| | 50 |
| 4 | Escreve 51 de volta na memória | | **51** |
| 5 | | Incrementa seu valor lido para 51| 51 |
| 6 | | Escreve 51 de volta na memória | **51** |

**O Problema:** Duas goroutines executaram a operação de incremento, mas o valor final de `i` só aumentou em 1. O incremento da Goroutine A foi **perdido**. Quando milhares de goroutines fazem isso, milhares de incrementos são perdidos, resultando em um valor final imprevisível. Isso é uma **condição de corrida**.

## 2\. A Solução: Exclusão Mútua com `sync.Mutex`

Para resolver isso, precisamos garantir que apenas **uma goroutine** possa executar a operação crítica (`i++`) de cada vez. Precisamos de um mecanismo de **exclusão mútua**, e a ferramenta padrão para isso em Go é o `sync.Mutex`.

Pense em um `Mutex` como uma "chave" para uma sala (a "seção crítica" do código).

1.  **`m.Lock()`:** "Eu quero entrar na sala." Se a porta estiver destrancada, a goroutine pega a chave, tranca a porta por dentro e continua. Se a porta já estiver trancada por outra goroutine, esta goroutine **espera (bloqueia)** na porta até que a chave seja devolvida.
2.  **`m.Unlock()`:** "Eu terminei o que estava fazendo na sala." A goroutine destranca a porta e devolve a chave, permitindo que a próxima goroutine em espera entre.

## 3\. Implementando a Solução Corretamente

Ao aplicar o `Mutex` em volta da nossa operação crítica, garantimos que a leitura, o incremento e a escrita de `i` aconteçam como uma única operação indivisível (atômica) do ponto de vista das outras goroutines.

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func main() {
	var i int
	// WaitGroup para garantir que todas as goroutines terminem
	var wg sync.WaitGroup
	// Nosso Mutex para proteger a variável 'i'
	var m sync.Mutex

	numGoroutines := 10000
	wg.Add(numGoroutines)

	for x := 0; x < numGoroutines; x++ {
		go func() {
			defer wg.Done()
			
			// 1. Tranca o acesso à variável 'i'.
			// Apenas uma goroutine pode passar deste ponto de cada vez.
			m.Lock()
			
			// --- Seção Crítica ---
			i++
			// --- Fim da Seção Crítica ---

			// 2. Libera o acesso para que outra goroutine possa prosseguir.
			m.Unlock()
		}()
	}

	// Espera todas as 10.000 goroutines terminarem
	wg.Wait()

	fmt.Println("Valor final de i:", i)
}
```

**Saída (agora sempre a mesma):**

```
Valor final de i: 10000
```

Sucesso\! Ao proteger o acesso concorrente à variável `i`, garantimos que nenhuma atualização seja perdida e o resultado final seja sempre o esperado.

## 4\. O "Go Way" e Considerações

  * **O Poder da Biblioteca Padrão `sync`:** Como a aula enfatiza, Go brilha ao fornecer ferramentas de concorrência poderosas e fáceis de usar diretamente em sua biblioteca padrão. `Mutex` e `WaitGroup` são dois dos pilares deste pacote.
  * **Quando Usar Mutex?** Use um `Mutex` sempre que você tiver múltiplas goroutines que precisam **ler e escrever** em uma área de memória compartilhada. Se as goroutines estivessem apenas lendo um valor que nunca muda, a proteção não seria necessária.
  * **Custo da Sincronização:** `Lock` e `Unlock` não são gratuitos. Eles adicionam uma pequena sobrecarga de sincronização. Em código de altíssima performance, é importante manter as "seções críticas" (o código entre `Lock` e `Unlock`) o mais curtas e rápidas possível para evitar que as goroutines passem muito tempo esperando.
  * **Honestidade do Instrutor:** O instrutor está correto ao dizer que em muitos códigos de aplicação de alto nível, você pode não usar `Mutex` diretamente com tanta frequência, pois as bibliotecas que você usa (como drivers de banco de dados) já lidam com a concorrência internamente. No entanto, entender como eles funcionam é absolutamente essencial para qualquer programador Go sério, especialmente ao escrever código de sistema ou lógica de negócio concorrente customizada.

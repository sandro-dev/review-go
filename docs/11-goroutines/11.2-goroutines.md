# **11.2: Concorrência na Prática com Goroutines**

Com a base teórica de concorrência e paralelismo estabelecida, esta aula nos mostra como é incrivelmente simples iniciar tarefas concorrentes em Go. Para isso, utilizamos a palavra-chave `go` e o conceito de **Goroutines**.

## 1\. O Que é uma Goroutine?

Uma goroutine é uma função que é executada de forma concorrente com outras funções. Pense nela como uma "thread super leve", gerenciada não diretamente pelo Sistema Operacional, mas pelo próprio **runtime do Go**.

  * **Runtime do Go:** É um conjunto de bibliotecas e um "gerente" que é compilado junto com seu programa. Uma de suas principais responsabilidades é o **Go Scheduler**, que gerencia a execução de todas as goroutines.

## 2\. Iniciando uma Goroutine: A Palavra-Chave `go`

A simplicidade de Go brilha aqui. Para executar qualquer função de forma concorrente (em uma nova goroutine), basta colocar a palavra-chave `go` na frente da chamada da função.

**Sintaxe:** `go nomeDaFuncao(argumentos)`

```go
package main

import (
	"fmt"
	"strconv"
)

func showMessage(mensagem string) {
	fmt.Println(mensagem)
}

func main() {
	for i := 0; i < 10; i++ {
		// Execução SÍNCRONA (padrão)
		// O programa espera a função terminar antes de continuar.
		showMessage(strconv.Itoa(i))
	}
}
```

**Saída Síncrona (previsível):**

```
0
1
2
...
9
```

Agora, vamos adicionar a palavra-chave `go` para tornar a chamada **assíncrona**.

```go
// ... (função showMessage)
func main() {
	for i := 0; i < 10; i++ {
		// Execução ASSÍNCRONA
		// O programa inicia a função em uma nova goroutine e
		// NÃO espera ela terminar. Ele continua a execução imediatamente.
		go showMessage(strconv.Itoa(i))
	}
}
```

## 3\. A "Pegadinha": O Programa que Não Imprime Nada

Ao executar o código assíncrono acima, o resultado mais provável é que **nada** seja impresso no console. Por quê?

**A Regra Mais Importante das Goroutines:**
O seu programa Go termina quando a **goroutine principal** (a que executa a função `main`) termina. Quando ela termina, **todas as outras goroutines em execução são encerradas abruptamente**, não importa o que estejam fazendo.

**Análise do Fluxo:**

1.  O laço `for` em `main` é executado muito rapidamente.
2.  Ele dispara 10 novas goroutines (com `go showMessage(...)`).
3.  A goroutine `main` chega ao fim do seu código e termina.
4.  As 10 goroutines que foram disparadas provavelmente nem tiveram tempo de serem agendadas pelo Go Scheduler para executar. Elas são "mortas" antes mesmo de começar.

A aula demonstra isso aumentando o loop para 10.000. O laço leva um pouco mais de tempo para ser concluído, o que dá "sorte" e tempo para *algumas* das goroutines rodarem e imprimirem seus números antes que a `main` termine.

## 4\. A Falta de Ordem: O Papel do Go Scheduler

Ao observar a saída do loop de 10.000, notamos que os números são impressos fora de ordem (`41`, `10`, `68`, ...).

  * **Por quê?** Isso acontece porque as goroutines são **concorrentes**. O Go Scheduler decide qual delas executar, quando e por quanto tempo, a fim de otimizar o uso da CPU. Não há nenhuma garantia de que a goroutine `0` será executada antes da `41`. Elas estão em uma "corrida", e a ordem em que terminam é indeterminada.

## 5\. O "Hack" para Esperar: `time.Sleep`

Para "consertar" o problema e dar tempo para as goroutines rodarem, a aula introduz uma solução simples, mas **não recomendada para produção**: `time.Sleep`.

```go
import (
    "time"
    // ...
)

func main() {
	for i := 0; i < 10; i++ {
		go showMessage(strconv.Itoa(i))
	}
	
	// Pausa a goroutine principal por 1 segundo, dando tempo para as outras rodarem.
	time.Sleep(1 * time.Second) 
}
```

Isso "funciona", mas é uma péssima prática. Você está apenas adivinhando quanto tempo as tarefas levarão. Em um programa real, usaremos ferramentas de sincronização adequadas, como **WaitGroups** e **Channels**, para esperar que as goroutines terminem de forma determinística.

## 6\. Goroutines vs. Threads do SO: A Vantagem de Performance

Este é o "molho secreto" de Go. A aula destaca a diferença de custo:

| Unidade de Concorrência | Custo de Memória (Inicial) | Gerenciada por |
| :--- | :--- | :--- |
| **Thread do SO** (Java, C\#, etc.) | \~1-2 MB | Sistema Operacional |
| **Goroutine** (Go) | **\~2 KB** (mil vezes menor\!) | Runtime do Go |

**Implicações:**

  * **Escalabilidade Massiva:** Como as goroutines são extremamente baratas, você pode ter centenas de milhares ou até milhões delas rodando em uma única aplicação sem esgotar a memória do sistema, algo impensável com threads do SO.
  * **Eficiência:** O Go Scheduler é otimizado para o modelo de Go. Ele mapeia as goroutines (M) para as threads do SO (N) em um modelo M:N, fazendo trocas de contexto muito mais rápidas do que o SO faria.

É por essa eficiência e escalabilidade que Go se tornou a linguagem preferida para a construção de servidores de rede, microsserviços e sistemas concorrentes de alta performance.

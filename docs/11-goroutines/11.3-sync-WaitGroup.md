# **11.3: Sincronização Elegante com `sync.WaitGroup`**

Na aula anterior, vimos que ao iniciar goroutines, a função `main` pode terminar antes delas, encerrando o programa prematuramente. Usamos `time.Sleep` como uma solução temporária, mas ela é falha por não ser determinística — você nunca sabe exatamente quanto tempo suas tarefas levarão.

Esta aula apresenta a solução idiomática e correta para este problema: o `sync.WaitGroup`.

## 1\. O Conceito: Um Contador de Goroutines

Pense em um `sync.WaitGroup` como um **contador de tarefas concorrentes**. Ele permite que a goroutine principal (ou qualquer outra) espere até que um grupo de outras goroutines tenha concluído seu trabalho.

Ele opera com base em três métodos principais:

1.  **`Add(n)`:** "Estou iniciando `n` tarefas que precisam ser concluídas." Você incrementa o contador.
2.  **`Done()`:** "Eu, uma das tarefas, acabei de terminar meu trabalho." Você decrementa o contador.
3.  **`Wait()`:** "Pause aqui e não continue até que o contador chegue a zero."

## 2\. Exemplo Prático: Executando Tarefas Independentes

Vamos recriar o cenário da aula, onde temos três tarefas independentes que podem ser executadas em paralelo para economizar tempo.

```go
package main

import (
	"fmt"
	"sync" // Importamos o pacote 'sync'
	"time"
)

// A função agora aceita um PONTEIRO para um WaitGroup
func callDatabase(wg *sync.WaitGroup) {
	// Defer garante que Done() será chamado, mesmo se houver um panic na função.
	defer wg.Done()
	
	fmt.Println("Iniciando chamada ao banco de dados...")
	time.Sleep(2 * time.Second)
	fmt.Println("Finalizado: callDatabase")
}

func callAPI(wg *sync.WaitGroup) {
	defer wg.Done()
	fmt.Println("Iniciando chamada à API externa...")
	time.Sleep(1 * time.Second)
	fmt.Println("Finalizado: callAPI")
}

func processInterno(wg *sync.WaitGroup) {
	defer wg.Done()
	fmt.Println("Iniciando processamento interno...")
	time.Sleep(1 * time.Second)
	fmt.Println("Finalizado: processInterno")
}

func main() {
	fmt.Println("Iniciando processos concorrentes...")
	
	// 1. Criamos nossa variável WaitGroup.
	var wg sync.WaitGroup

	// 2. Adicionamos 3 ao contador, pois vamos iniciar 3 goroutines.
	wg.Add(3)

	// 3. Iniciamos as goroutines, passando o ENDEREÇO do nosso WaitGroup.
	go callDatabase(&wg)
	go callAPI(&wg)
	go processInterno(&wg)

	// 4. A função main irá bloquear nesta linha até que o contador do WaitGroup chegue a 0.
	wg.Wait()

	fmt.Println("Todos os processos foram finalizados. Encerrando o programa.")
}
```

**Saída:**

```
Iniciando processos concorrentes...
Iniciando chamada ao banco de dados...
Iniciando chamada à API externa...
Iniciando processamento interno...
Finalizado: callAPI
Finalizado: processInterno
Finalizado: callDatabase
Todos os processos foram finalizados. Encerrando o programa.
```

**Análise do Tempo:** A tarefa mais longa (`callDatabase`) leva 2 segundos. O programa inteiro termina em aproximadamente 2 segundos, não nos 4 segundos que levaria se fosse executado de forma sequencial. Conseguimos o paralelismo\!

## 3\. A "Pegadinha" Crucial: Cópia por Valor vs. Ponteiros

A aula demonstra um dos erros mais comuns e importantes ao usar `sync.WaitGroup`. O que acontece se passarmos o `WaitGroup` por valor, em vez de por ponteiro?

**O Problema:**
Se a assinatura da função fosse `func callDatabase(wg sync.WaitGroup)` (sem o `*`), ao chamá-la com `go callDatabase(wg)`, Go faria uma **cópia** do `WaitGroup` para a goroutine.

1.  A `wg` na `main` tem um contador `3`.
2.  Uma cópia da `wg`, com contador `0`, é enviada para `callDatabase`.
3.  Dentro de `callDatabase`, `wg.Done()` é chamado na **cópia**, decrementando seu contador para `-1`.
4.  O contador da `wg` **original**, na `main`, **nunca é alterado**. Ele permanece em `3`.
5.  `wg.Wait()` na `main` fica esperando para sempre o contador chegar a zero, o que nunca acontece.

**O Resultado:** O programa trava em um **deadlock**, como a aula mostrou.

**A Solução:**
Ao passar um **ponteiro** (`&wg`) e aceitar um ponteiro (`*sync.WaitGroup`), garantimos que todas as goroutines e a função `main` estão olhando e modificando o **mesmo e único contador**. É por isso que o uso de ponteiros aqui não é opcional, é **obrigatório**.

## 4\. O "Go Way": `defer wg.Done()`

É uma prática de segurança muito comum e recomendada colocar a chamada `wg.Done()` dentro de uma instrução `defer` no início da sua goroutine.

```go
func myFunc(wg *sync.WaitGroup) {
    defer wg.Done()
    // ... resto do código da função
}
```

Isso garante que o contador será decrementado, não importa como a função termine — seja por um retorno normal no final ou por um `panic` no meio do caminho. Isso torna seu código de sincronização muito mais robusto.

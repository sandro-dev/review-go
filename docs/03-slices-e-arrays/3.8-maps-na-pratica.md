# **3.8: Manipulando Maps na Prática**

Com a teoria estabelecida, esta aula nos mostra como, na prática, criar, popular, atualizar e consultar maps em Go. Exploramos as duas formas principais de inicialização e o padrão fundamental para verificar se uma chave existe antes de usar seu valor.

## 1\. Criando e Inicializando Maps

Assim como os slices, Go nos oferece duas maneiras principais de criar um map.

### a) Forma 1: O Literal Composto (Quando os Dados são Conhecidos)

Esta é a forma mais direta de criar um map quando você já sabe quais serão os pares chave-valor iniciais.

**Sintaxe:** `map[TipoChave]TipoValor{chave1: valor1, chave2: valor2, ...}`

```go
package main

import "fmt"

func main() {
	// Cria e inicializa um map com chaves string e valores int.
	populacaoCidades := map[string]int{
		"São Paulo": 10000000,
		"CG":        900000,
	}

	fmt.Println("Map criado com literal:", populacaoCidades)
}
```

**Saída:**

```
Map criado com literal: map[CG:900000 São Paulo:10000000]
```

*(Lembre-se: a ordem de impressão dos elementos de um map não é garantida).*

### b) Forma 2: A Função `make` (Para Preenchimento Dinâmico)

Quando você precisa criar um map vazio para populá-lo depois (por exemplo, dentro de um laço ou com base em entrada do usuário), a função `make` é a ferramenta ideal.

**Sintaxe:** `make(map[TipoChave]TipoValor)`

```go
// (continuação do código acima)
// Cria um map vazio, pronto para receber dados.
populacaoCidadesMake := make(map[string]int)
fmt.Println("Map criado com make (vazio):", populacaoCidadesMake)
```

## 2\. Adicionando, Acessando e Atualizando Elementos

A sintaxe para adicionar um novo par, acessar o valor de uma chave existente ou atualizar um valor é exatamente a mesma, o que torna a manipulação de maps muito intuitiva.

**Sintaxe:** `meuMap["chave"] = valor`

  * Se a chave **não existe**, um novo par chave-valor é **criado**.
  * Se a chave **já existe**, o valor associado a ela é **atualizado (sobrescrito)**.

<!-- end list -->

```go
// (continuação do código principal)
populacaoCidadesMake["São Paulo"] = 10000000 // Adicionando o primeiro par
populacaoCidadesMake["CG"] = 900000        // Adicionando o segundo par

fmt.Println("Map após adições:", populacaoCidadesMake)
```

## 3\. A Unicidade das Chaves

Um dos princípios fundamentais de um map é que **cada chave deve ser única**. Como a aula demonstrou, se você tentar atribuir um valor a uma chave que já existe, você não cria uma duplicata; você **atualiza** o valor original.

```go
// (continuação do código principal)
fmt.Println("\n--- Teste de Unicidade de Chave ---")
fmt.Println("Valor de 'CG' antes:", populacaoCidadesMake["CG"])

// Atribuindo um novo valor para a mesma chave 'CG'
populacaoCidadesMake["CG"] = 700000

fmt.Println("Valor de 'CG' depois:", populacaoCidadesMake["CG"])
fmt.Println("Map completo:", populacaoCidadesMake)
```

**Saída:**

```
--- Teste de Unicidade de Chave ---
Valor de 'CG' antes: 900000
Valor de 'CG' depois: 700000
Map completo: map[CG:700000 São Paulo:10000000]
```

## 4\. Verificando a Existência de uma Chave: O Idioma "comma, ok"

O que acontece se tentarmos acessar uma chave que não existe, como `"Rio de Janeiro"`? O programa não quebra. Em vez disso, ele retorna o **valor zero** do tipo do valor (neste caso, `0` para `int`). Isso pode levar a bugs, pois não sabemos se o valor é realmente zero ou se a chave simplesmente não existe.

Para resolver isso, Go oferece um padrão idiomático e seguro conhecido como **"comma, ok"**. Ao acessar uma chave, você pode, opcionalmente, receber um segundo valor: um booleano que indica se a chave foi encontrada.

**Sintaxe:** `valor, ok := meuMap["chave"]`

  * `valor`: Contém o valor associado à chave (ou o valor zero se não for encontrada).
  * `ok` (ou `existe`, `encontrado`): É uma variável booleana. Será `true` se a chave foi encontrada, e `false` caso contrário.

<!-- end list -->

```go
// (continuação do código principal)
fmt.Println("\n--- Verificação 'comma, ok' ---")

// Tentando acessar uma chave que NÃO existe
valorRJ, encontradoRJ := populacaoCidadesMake["Rio de Janeiro"]
if encontradoRJ {
	fmt.Println("A população do Rio de Janeiro é:", valorRJ)
} else {
	fmt.Println("A chave 'Rio de Janeiro' não foi encontrada.")
	fmt.Printf("O valor retornado foi o valor zero do tipo: %d\n", valorRJ)
}
```

**Saída:**

```
--- Verificação 'comma, ok' ---
A chave 'Rio de Janeiro' não foi encontrada.
O valor retornado foi o valor zero do tipo: 0
```

Este padrão é a forma correta e segura de consultar um map em Go.

## 5\. Bônus: A Declaração `if` com Inicializador

A aula introduz uma forma de sintaxe em Go que combina a declaração de uma variável e a condição em uma única linha `if`.

**Sintaxe:** `if <declaração>; <condição> { ... }`

Isso é muito comum de ser usado com o padrão "comma, ok".

```go
// Forma tradicional, com variáveis declaradas antes
valorSP, encontradoSP := populacaoCidadesMake["São Paulo"]
if encontradoSP {
    // ...
}

// Forma com inicializador (mais idiomática em Go para este caso)
if valorSP, encontradoSP := populacaoCidadesMake["São Paulo"]; encontradoSP {
	fmt.Println("Verificação com 'if-initializer': A população de SP é", valorSP)
}
```

**Vantagem:** As variáveis `valorSP` e `encontradoSP` declaradas desta forma têm seu **escopo limitado** ao bloco `if/else`. Elas não "vazam" para o resto da função, o que ajuda a manter o código mais limpo e organizado. A escolha entre os dois estilos é uma preferência, mas a forma com inicializador é muito prevalente na comunidade Go.

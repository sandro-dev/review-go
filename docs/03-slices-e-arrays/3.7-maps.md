# **3.7: Introdução a Maps - Coleções Chave-Valor**

Até agora, nossas coleções (arrays e slices) eram acessadas por um índice numérico sequencial (0, 1, 2, ...). Nesta aula, introduzimos uma nova forma de agrupar dados, muito mais flexível e descritiva: os **Maps**.

## 1. O Que é um Map?

Um **map** em Go é uma coleção **não ordenada** de pares **chave-valor**.

Pense nele como um dicionário do mundo real:
* A **chave** é a palavra que você procura.
* O **valor** é a definição associada àquela palavra.

Em um map, você usa uma chave única para armazenar e recuperar um valor associado.

## 2. O Problema que os Maps Resolvem: A Limitação do Índice Numérico

A aula ilustra perfeitamente o "porquê" da existência dos maps, comparando-os com as listas (slices) que já conhecemos.

**O Cenário:** Armazenar a população de várias cidades.

### a) A Abordagem com Slice (A Problemática)
Se usarmos um slice, teremos uma lista de números.

`populacoes := []int{900000, 10000000, 500000, 2000000}`

* **A Fragilidade:** Para saber a população de São Paulo, eu preciso *saber de antemão* e *lembrar* que ela está na posição de **índice 1**. Se a ordem da lista mudar, ou se uma nova cidade for inserida no início, todo o meu conhecimento sobre os índices se torna inválido. O índice numérico não tem um significado intrínseco; ele é apenas uma posição.

### b) A Abordagem com Map (A Solução Elegante)
Com um map, podemos associar diretamente o nome da cidade (a chave) à sua população (o valor).

`populacoes := map[string]int{"Campo Grande": 900000, "São Paulo": 10000000, ...}`

* **A Robustez:** Agora, para saber a população de São Paulo, eu não preciso saber de nenhuma posição. Eu simplesmente peço o valor associado à chave `"São Paulo"`: `populacoes["São Paulo"]`. A chave tem um **significado real**, tornando o código muito mais legível, intuitivo e menos propenso a erros.

## 3. Características Fundamentais de um Map em Go

1.  **Pares Chave-Valor:** Todo item em um map consiste em uma chave e um valor correspondente.
2.  **Tipos Flexíveis:** Como a aula mencionou, a chave e o valor podem ter tipos diferentes. Você pode ter uma chave `string` e um valor `int`, uma chave `int` e um valor `string`, e assim por diante.
3.  **Unicidade das Chaves:** Cada chave dentro de um map **deve ser única**. Se você tentar adicionar um novo valor com uma chave que já existe, o valor antigo será **sobrescrito**.
4.  **Não Ordenado (Unordered):** Esta é uma diferença crucial em relação aos slices. Os elementos em um map **não têm uma ordem garantida**. Ao iterar sobre um map, você não pode assumir que os itens aparecerão na mesma ordem em que foram inseridos.
5.  **Acesso Rápido:** Maps são altamente otimizados para buscas. Acessar um valor por sua chave é uma operação extremamente rápida, independentemente do número de itens no map.

## 4. Analogia com Outras Linguagens

O conceito de map não é exclusivo de Go. Se você vem de outras linguagens, provavelmente já o conhece por outro nome.

| Linguagem | Nome da Estrutura |
| :--- | :--- |
| **Go** | **Map** |
| Python | Dictionary (`dict`) |
| C#, .NET | Dictionary |
| Java | HashMap |
| JavaScript | Object / Map |
| Ruby | Hash |

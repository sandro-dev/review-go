# **4.5: Entendendo Escopo de Variáveis**

Nesta aula, exploramos o conceito de **escopo**, que define a "região" do código onde uma variável é visível e pode ser acessada. O escopo determina o ciclo de vida de uma variável e quem pode "enxergá-la".

## 1\. O Conceito de Escopo

Pense no escopo como os cômodos de uma casa. Uma variável declarada dentro de um quarto (uma função) só é conhecida e utilizável dentro daquele quarto. Ninguém na sala de estar (outra função) sabe que ela existe. Já uma variável declarada no corredor principal da casa (nível do pacote) pode ser vista e acessada por quem está em qualquer um dos quartos.

Em Go, os dois principais níveis de escopo que a aula aborda são:

  * **Escopo de Função (ou Bloco):** O escopo mais interno.
  * **Escopo de Pacote:** Um escopo mais externo, compartilhado pelos arquivos do mesmo pacote.

## 2\. Escopo de Função (Variáveis Locais)

Quando você declara uma variável **dentro** de uma função, ela possui **escopo de função**.

  * **Visibilidade:** Ela só é visível e acessível dentro daquela função.
  * **Ciclo de Vida:** Ela é "criada" quando a função é chamada e "destruída" quando a função termina sua execução.

**Exemplo Prático (Demonstrando o Erro):**

A aula demonstra isso perfeitamente. A variável `numeroMagico` é criada dentro da função `operacoes`. A função `main` não tem como saber de sua existência.

```go
package main

import "fmt"

func operacoes(n1, n2 int) int {
	// 'numeroMagico' é declarada AQUI. Seu escopo está limitado à função 'operacoes'.
	numeroMagico := 5
	soma := n1 + n2 + numeroMagico
	return soma
}

func main() {
	resultadoSoma := operacoes(1, 2)
	fmt.Println("O resultado da soma foi:", resultadoSoma)

	// A linha abaixo, se descomentada, causará um erro de compilação.
	// fmt.Println(numeroMagico) // Erro: undefined: numeroMagico
}
```

O erro `undefined: numeroMagico` (indefinido) acontece porque, do ponto de vista da função `main`, a variável `numeroMagico` simplesmente não existe.

## 3\. Escopo de Pacote (Variáveis "Globais" ao Pacote)

Quando você declara uma variável **fora** de qualquer função, mas dentro do pacote, ela possui **escopo de pacote**.

  * **Visibilidade:** Ela é visível e acessível por **todas** as funções declaradas no mesmo pacote (no nosso caso, no mesmo arquivo).
  * **Ciclo de Vida:** Ela existe durante toda a execução do programa.

**Exemplo Prático (Código Corrigido):**

```go
package main

import "fmt"

// 'numeroMagico' agora está no escopo do pacote.
// 'main' e 'operacoes' podem vê-la.
var numeroMagico int = 5

func operacoes(n1, n2 int) int {
	// Acessa a variável do escopo do pacote.
	soma := n1 + n2 + numeroMagico
	return soma
}

func main() {
	resultadoSoma := operacoes(1, 2)
	
	// 'main' agora pode subtrair o valor, pois tem acesso a ele.
	somaReal := resultadoSoma - numeroMagico

	fmt.Printf("Resultado da função: %d\n", resultadoSoma)
	fmt.Printf("Número mágico acessado em main: %d\n", numeroMagico)
	fmt.Printf("Soma real (após subtração): %d\n", somaReal)
}
```

**Saída:**

```
Resultado da função: 8
Número mágico acessado em main: 5
Soma real (após subtração): 3
```

Agora o código funciona como esperado, pois ambas as funções compartilham o acesso à mesma variável `numeroMagico`.

## 4\. O Perigo: Shadowing de Variáveis

A aula termina com um exemplo crucial que ilustra um conceito chamado **shadowing** (sombreamento). Isso ocorre quando você declara uma variável em um escopo mais interno com o **mesmo nome** de uma variável em um escopo mais externo.

A variável interna "esconde" ou "projeta uma sombra" sobre a externa, que se torna inacessível dentro daquele escopo interno.

```go
package main

import "fmt"

var numeroMagico int = 5 // Variável no escopo do PACOTE

func operacoes(n1, n2 int) int {
	// Esta linha cria uma NOVA variável 'numeroMagico' que só existe AQUI DENTRO.
	// Ela "esconde" a variável de pacote.
	numeroMagico := 3 // Shadowing!

	fmt.Printf("(Dentro de 'operacoes', numeroMagico é %d)\n", numeroMagico)
	soma := n1 + n2 + numeroMagico
	return soma
}

func main() {
	fmt.Printf("(Em 'main', antes, numeroMagico é %d)\n", numeroMagico)
	
	resultadoSoma := operacoes(1, 2) // operacoes usará o valor 3

	fmt.Printf("(Em 'main', depois, numeroMagico AINDA é %d)\n", numeroMagico)
	fmt.Printf("Resultado da função: %d\n", resultadoSoma) // Será 1 + 2 + 3 = 6

	somaReal := resultadoSoma - numeroMagico // Subtrairá 5!
	fmt.Printf("Resultado 'correto' esperado (errado): %d\n", somaReal) // Será 6 - 5 = 1
}
```

**Saída:**

```
(Em 'main', antes, numeroMagico é 5)
(Dentro de 'operacoes', numeroMagico é 3)
(Em 'main', depois, numeroMagico AINDA é 5)
Resultado da função: 6
Resultado 'correto' esperado (errado): 1
```

Este é um bug clássico e difícil de encontrar. A função `operacoes` trabalhou com o valor `3`, mas a função `main` continuou trabalhando com o valor `5`, levando a um cálculo incorreto.

## 5\. Boas Práticas e o "Go Way"

  * **Prefira o Menor Escopo Possível:** Sempre declare suas variáveis no escopo mais restrito em que elas são necessárias. Se uma variável só é usada dentro de uma função, declare-a dentro da função. Isso torna seu código mais fácil de entender e evita efeitos colaterais indesejados.
  * **Use Variáveis de Pacote com Cuidado:** Variáveis "globais" podem ser perigosas porque qualquer função pode modificá-las, tornando o estado do seu programa difícil de rastrear. Elas são mais adequadas para constantes (`const`) ou para estados que são verdadeiramente globais e gerenciados com cuidado (como pools de conexão com banco de dados).
  * **Evite o Shadowing:** Seja deliberado com os nomes de suas variáveis para não esconder acidentalmente uma variável de um escopo externo. Ferramentas de lint (análise de código) para Go frequentemente alertam sobre shadowing.

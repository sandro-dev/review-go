# **4.4: Retornos Nomeados (Named Return Values)**

Na aula anterior, vimos como uma função em Go pode retornar múltiplos valores. Nesta aula, exploramos uma sintaxe adicional para essa funcionalidade: os **retornos nomeados**. Essa técnica consiste em dar nomes às variáveis de retorno diretamente na assinatura da função, o que pode servir como uma forma de documentação e, em alguns casos, simplificar o corpo da função.

## 1\. O Conceito: O Que São Retornos Nomeados?

Em vez de apenas declarar os *tipos* dos valores de retorno, você declara o **nome** e o **tipo** de cada um.

**Antes (Retornos Anônimos):**
`func operacoes(n1 int, n2 int) (int, int, int, int)`

**Depois (Retornos Nomeados):**
`func operacoes(n1 int, n2 int) (soma int, subtracao int, divisao int, multiplicacao int)`

## 2\. As Vantagens na Prática

Ao usar retornos nomeados, duas coisas mudam dentro da função, como a aula demonstrou.

### a) Variáveis de Retorno Pré-Declaradas

As variáveis que você nomeou na assinatura (`soma`, `subtracao`, etc.) já estão **declaradas e inicializadas com seus valores zero** no escopo da função. Isso significa que você não precisa (e não deve) usar o operador de declaração curta `:=` para elas. Você apenas as utiliza e atribui valores a elas.

### b) O `return` "Vazio" (Bare Return)

Você pode usar a palavra-chave `return` sozinha. Quando um `return` vazio é encontrado, a função automaticamente retorna os **valores atuais** de todas as suas variáveis de retorno nomeadas, na ordem em que foram declaradas.

## 3\. Exemplo Prático: Refatorando a Função `operacoes`

Vamos comparar as duas versões lado a lado para ver a diferença claramente.

**Versão 1: Sem Retornos Nomeados (Aula Anterior)**

```go
func operacoesSemNomes(numero1 int, numero2 int) (int, int, int, int) {
	soma := numero1 + numero2
	subtracao := numero1 - numero2
	divisao := numero1 / numero2
	multiplicacao := numero1 * numero2

	return soma, subtracao, divisao, multiplicacao
}
```

**Versão 2: Com Retornos Nomeados (Esta Aula)**

```go
package main

import "fmt"

// As variáveis 'soma', 'subtracao', etc., são declaradas aqui.
func operacoesComNomes(numero1 int, numero2 int) (soma int, subtracao int, divisao int, multiplicacao int) {
	// Não usamos ':=', apenas '=' para atribuir valores às variáveis já declaradas.
	soma = numero1 + numero2
	subtracao = numero1 - numero2
	multiplicacao = numero1 * numero2
	if numero2 != 0 {
		divisao = numero1 / numero2
	}
	
	// Um 'return' vazio retorna os valores atuais de soma, subtracao, divisao e multiplicacao.
	return
}

func main() {
	// A chamada da função e a captura dos valores são idênticas.
	s, sub, d, m := operacoesComNomes(10, 2)
	fmt.Printf("Soma: %d, Subtração: %d, Divisão: %d, Multiplicação: %d\n", s, sub, d, m)
}
```

**Saída:**

```
Soma: 12, Subtração: 8, Divisão: 5, Multiplicação: 20
```

O resultado final é exatamente o mesmo, mas a implementação da função é diferente.

## 4\. O "Go Way": Prós e Contras

A aula destaca as vantagens de usar retornos nomeados, mas como bons engenheiros, devemos também conhecer as desvantagens.

**Prós (Vantagens):**

  * **Auto-documentação:** A principal vantagem. Qualquer pessoa que leia a assinatura da função sabe imediatamente o que cada valor de retorno significa, sem precisar ler o código interno. `(soma int)` é muito mais claro que apenas `(int)`.
  * **Código mais limpo (em alguns casos):** Em funções curtas, a combinação de variáveis pré-declaradas e um `return` vazio pode reduzir a verbosidade.

**Contras (Pontos de Atenção):**

  * **Risco do `return` Vazio:** Em funções mais longas ou com múltiplos pontos de retorno (vários `if`s), um `return` vazio pode **prejudicar a legibilidade**. O leitor do código pode não saber imediatamente quais valores estão sendo retornados sem ter que rolar até a assinatura da função.
  * **Shadowing Acidental:** Se, por descuido, você usar `:=` dentro da função para uma variável com o mesmo nome de um retorno nomeado (ex: `soma := ...`), você criará uma nova variável local que "esconde" (shadows) a variável de retorno. O `return` vazio então retornaria o valor zero da variável de retorno original, e não o valor que você acabou de calcular, levando a bugs sutis.

**Recomendação:**

  * Use retornos nomeados sempre que isso **melhorar a clareza** da sua função, principalmente como forma de documentação.
  * Use o `return` vazio **com cautela**. Ele é mais adequado para funções curtas e simples, onde o fluxo é óbvio. Em funções mais complexas, ser explícito (`return soma, subtracao, ...`) é muitas vezes a escolha mais segura e legível.
